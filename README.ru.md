# hermes-field-notes

**Полевые заметки установки Hermes Agent:** грабли с причиной и обходом, локальные патчи ядра
Hermes с проверкой после каждого `hermes update` и, по желанию, закреплённый дашборд в Telegram.

[English version](README.md)

Любая долго живущая установка Hermes копит два вида дорогого знания, которое тихо теряется:

- **грабли** — «cron молчал, потому что у пользовательского сервиса не было linger», «двоеточие без
  кавычек в описании скилла — и загрузчик плагинов молча его выбрасывает». В первый раз это час
  диагностики, через месяц — тот же час, если никто не записал;
- **локальные патчи ядра** — маленькие правки внутри `hermes-agent`, которые `hermes update` стирает.
  Узнаёшь об этом, когда баг возвращается.

Скилл даёт агенту одно место для обоих и делает патчи проверяемыми.

## Что умеет

- **Искать до починки.** `fieldnotes.py search <текст ошибки>` ищет по вашим заметкам и по
  встроенному списку проверенных граблей Hermes
  ([`known-pitfalls.md`](skills/hermes-field-notes/references/known-pitfalls.md), на английском).
- **Записывать после разбора.** Заметка — Markdown-файл с коротким frontmatter; `INDEX.md`
  собирается командой, руками не правится. `lint` ловит битые поля, устаревшие заметки и то, что
  похоже на секреты.
- **Каждая правка ядра — заметка-патч** с декларативным файлом проверок: какие признаки должны быть
  в каком файле ядра для какой версии и какие признаки значат, что фикс уже в апстриме.
- **После апдейта `doctor`** только чтением показывает, какие патчи `OK`, `MISSING`, `UPSTREAMED`,
  `N/A` или `UNKNOWN` (с причиной), какие файлы ядра изменены мимо реестра и какие заметки
  проверялись на другом ядре.
- **Закреплённый дашборд** (по желанию): одно сообщение в Telegram, бот агента правит его на месте, а
  отдельная строка-алерт приходит, только когда что-то изменилось. Работает cron-задачей `no_agent` —
  без вызова модели и без токенов.
- **Черновики для апстрима.** `issue-draft <id>` делает из заметки-багфикса черновик issue с
  маскировкой. Публикует всегда человек.

Скилл не правит ядро и не запускает патч-скрипты: он записывает, проверяет и напоминает.

## Установка

Как обычный скилл (рекомендуется — агент находит его по описанию):

```bash
hermes skills install itpartypattaya/hermes-field-notes/skills/hermes-field-notes
```

Или как плагин (ставится выключенным; после включения имя скилла получает префикс плагина):

```bash
hermes plugins install itpartypattaya/hermes-field-notes
hermes plugins enable hermes-field-notes
```

Затем хранилище и конфиг, и проверка:

```bash
python3 ~/.hermes/skills/hermes-field-notes/scripts/install.py
python3 ~/.hermes/skills/hermes-field-notes/scripts/install.py --check
```

Ежечасная проверка и дашборд — сначала поправьте `~/.hermes/field-notes.json`
(`dashboard.enabled`, `chat_id`, `thread_id`, `language: "ru"`, `timezone`), затем:

```bash
~/.hermes/hermes-agent/venv/bin/python ~/.hermes/skills/hermes-field-notes/scripts/install_cron.py --dry-run
~/.hermes/hermes-agent/venv/bin/python ~/.hermes/skills/hermes-field-notes/scripts/install_cron.py
```

Нужно: Hermes Agent ≥ 0.21 (писалось под 0.21.5), Python 3.11+, только стандартная библиотека.
Для проверки патчей ядро должно лежать каталогом; для `drift` — ещё и быть git-чекаутом.

## Как пользоваться

Просто просите агента: «что мы знаем про эту ошибку?», «запиши это», «патчи пережили апдейт?»,
«покажи дашборд». Или запускайте скрипт сами:

```bash
FN=~/.hermes/skills/hermes-field-notes/scripts/fieldnotes.py
python3 $FN search "no_agent" "silent"
python3 $FN new cron-linger --area cron --title "Cron-воркер не стартует без linger"
python3 $FN new quota-auth --type patch --area gateway --title "429 показывается как ошибка авторизации"
python3 $FN index && python3 $FN lint
python3 $FN doctor
python3 $FN dashboard --format md
```

`--read-only` у любой команды гарантирует: ни записи, ни сети.

## Что на дашборде

Первая строка видна прямо в плашке закрепа: версия ядра, сколько патчей на месте и слетело, число
заметок. Внутри — ядро (версия, тег, SHA, когда обновлено и что было до, изменения ядра вне
реестра), патчи (багфиксы и настройки, статусы, принятые апстримом, багфиксы без issue, сколько
файлов ядра под патчами, возраст, раскрывающийся список), заметки (новые за 30 дней, что
перепроверить на этом ядре, неподтверждённые гипотезы, области, где чаще ломается) и время проверки.
Зачем каждая цифра — [`dashboard.md`](skills/hermes-field-notes/references/dashboard.md).

## Приватность и безопасность

- Заметки остаются на вашей машине (`$HERMES_HOME/field-notes/`), никуда не выгружаются.
- Сеть — только Telegram Bot API, только при включённом дашборде и только в заданный чат. Токен
  бота берётся из окружения или `$HERMES_HOME/.env` и нигде не печатается.
- Запись — хранилище заметок, `$HERMES_HOME/cache/field-notes-state.json`, копия cron-скрипта в
  `$HERMES_HOME/scripts/` и cron-задача, если запустить `install_cron.py`. Ядро только читается.
